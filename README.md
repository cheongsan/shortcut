# CHEONGSANDO Shortcut

Notion 데이터베이스에 적어 둔 주소를 짧은 키로 열어주는 바로가기 서비스입니다.

`cs.io.kr/example` 처럼 접속하면 **바로 이동하지 않고** 목적지의 미리보기 이미지·제목·주소를
먼저 보여주고, 사용자가 **이동 버튼을 눌러야** 이동합니다. 키 없이 `cs.io.kr` 으로 접속하면
키를 입력하는 화면이 나옵니다.

바로가기를 추가·수정하려면 **Notion 표에 한 줄 쓰면 됩니다.** 코드를 고치거나 다시 배포할
필요가 없습니다.

## 1. 배포 전에 준비할 것

세 가지만 있으면 됩니다.

| 준비물 | 어디서 |
|---|---|
| Notion 계정 | 바로가기 표를 둘 워크스페이스 |
| Vercel 계정 | <https://vercel.com> — GitHub 계정으로 로그인 가능 |
| 이 저장소 접근 권한 | Vercel이 코드를 읽어갑니다 |

**직접 준비할 게 아닌 것**: 서버, 데이터베이스, 도메인(없어도 Vercel이 주소를 하나 줍니다).

소요 시간은 처음 해보실 경우 15~20분 정도입니다.

## 2. Notion 데이터베이스 만들기

Notion에서 새 페이지를 만들고 **표(Table)** 를 하나 추가합니다.
그리고 아래 속성을 **표에 있는 이름과 타입 그대로** 만들어 주세요.

| 속성 이름 | 타입 | 필수 | 무엇을 적나요 |
|---|---|---|---|
| `Key` | **제목(Title)** | ✅ | 바로가기 키. 이 값이 주소가 됩니다 → `cs.io.kr/여기` |
| `URL` | **URL** | ✅ | 이동할 목적지 주소 |
| `Enabled` | **선택(Select)** | ✅ | `Enabled` 또는 `Disabled` |
| `Title` | 텍스트(Rich text) | | 확인 화면에 보일 제목 |
| `Description` | 텍스트(Rich text) | | 확인 화면에 보일 설명 |
| `Aliases` | 다중 선택(Multi-select) | | 같은 목적지를 가리키는 다른 키 |

> **이름이 하나라도 다르면 동작하지 않습니다.** 대소문자까지 정확히 맞춰 주세요.
> 다행히 조용히 실패하지는 않습니다 — 이름이 틀리면 서버 로그에 어떤 속성을 확인해야
> 하는지 그대로 찍힙니다.

### 채울 때 알아두면 좋은 것

**`Key` 는 소문자·숫자·`-`·`_` 만 쓸 수 있고 최대 64자입니다.**
점(`.`)과 공백은 쓸 수 없습니다. 대문자로 적어도 자동으로 소문자로 맞춰 읽습니다
(`/EXAMPLE` 로 접속하면 `/example` 로 안내됩니다).

`api`, `_next`, `icon`, `opengraph-image`, `static` 다섯 개는 시스템이 쓰는 이름이라
키로 사용할 수 없습니다.

**`Enabled` 선택 옵션은 `Enabled` / `Disabled` 두 개를 정확히 이 철자로 만들어 주세요.**
Notion은 대소문자나 공백을 알아서 맞춰주지 않으므로 `enabled` 나 `Enabled `(뒤에 공백)는
다른 값으로 취급됩니다.

**값을 고르지 않은 줄은 "꺼짐"으로 처리됩니다.** 새 줄을 추가하면 기본적으로 비어 있으니,
`Enabled` 를 골라주기 전까지는 공개되지 않습니다. 실수로 공개되는 일을 막기 위한 동작입니다.

**`Title` 을 비우면** 목적지 주소(예: `github.com`)가 대신 제목으로 표시됩니다.

**`Aliases`** 옵션 이름에는 쉼표를 쓸 수 없습니다(Notion 제약). 같은 키가 `Key` 와
`Aliases` 양쪽에 있으면 `Key` 가 이깁니다.

### 예시

| Key | URL | Enabled | Title | Description |
|---|---|---|---|---|
| `example` | `https://github.com/cheongsan/shortcut` | `Enabled` | 예시 바로가기 | 이 저장소로 이동합니다 |
| `wiki` | `https://notion.so/...` | `Enabled` | 팀 위키 | |
| `old-link` | `https://...` | `Disabled` | | 잠시 내려둔 링크 |

## 3. Notion 인테그레이션 연결하기

서비스가 표를 읽을 수 있게 권한을 주는 단계입니다.

**1단계 — 인테그레이션 만들기**

<https://www.notion.so/my-integrations> 에서 **New integration** 을 누릅니다.
권한은 **Read content** 하나만 있으면 충분합니다.
만들고 나면 나오는 **시크릿**(`ntn_` 으로 시작. 예전에 만든 것은 `secret_`)을 복사해 둡니다.
이 값이 `NOTION_TOKEN` 입니다.

**2단계 — 표에 연결하기 (가장 많이 놓치는 단계입니다)**

만들어 둔 Notion 데이터베이스 페이지를 열고,
오른쪽 위 **`⋯`** → **Connections** → 방금 만든 인테그레이션을 추가합니다.

> 인테그레이션을 만들기만 하면 아무 표도 읽을 수 없습니다. **표마다 따로 연결해야 합니다.**
> 이 단계를 빠뜨리면 Notion이 "그런 데이터베이스가 없다"(`object_not_found`)고 답하는데,
> 실제로는 권한 문제라서 헷갈리기 쉽습니다. → [문제가 생겼을 때](#7-문제가-생겼을-때)

**3단계 — 데이터베이스 주소 복사하기**

데이터베이스 페이지에서 **Share** → **Copy link** 로 주소를 복사합니다.
이 주소를 그대로 `NOTION_DATABASE_ID` 에 넣으면 됩니다. **주소에서 ID만 잘라낼 필요는
없습니다** — 알아서 추출합니다.

## 4. 환경변수

Vercel에 넣을 값입니다. 필수는 **두 개**뿐입니다.

| 이름 | 필수 | 값 |
|---|---|---|
| `NOTION_TOKEN` | ✅ | 인테그레이션 시크릿 (`ntn_…`) |
| `NOTION_DATABASE_ID` | ✅ | 데이터베이스 링크 (URL 그대로 붙여넣기) |
| `NEXT_PUBLIC_SITE_URL` | 권장 | 서비스의 실제 주소 (예: `https://cs.io.kr`) |
| `NOTION_DATA_SOURCE_ID` | 선택 | 넣으면 조금 빨라집니다 (아래 설명) |

### `NEXT_PUBLIC_SITE_URL`

미리보기 카드의 메타 정보와 `robots.txt` 에 쓰입니다. 없어도 동작하지만, 도메인을
연결한 뒤에는 채워주시는 편이 좋습니다. **끝에 `/` 를 붙이지 마세요.**

### `NOTION_DATA_SOURCE_ID` (선택)

비워두면 서비스가 시작할 때 알아서 찾습니다. 다만 그때마다 Notion에 한 번 더 물어보므로,
직접 넣어두면 첫 응답이 조금 빨라집니다.

값을 알고 싶으면 이 저장소를 내려받아 한 번 실행하면 출력됩니다
([9번 항목](#9-내-컴퓨터에서-실행해-보기) 참고):

```bash
npm run notion:datasource
```

> 데이터베이스에 여러 데이터 소스(뷰의 원본)가 있는 경우에는 **직접 지정하는 편이
> 안전합니다.** 비워두면 그중 어느 것이 선택될지 보장되지 않습니다.

### 절대 저장소에 올리지 마세요

`NOTION_TOKEN` 은 표를 읽을 수 있는 열쇠입니다. Vercel의 환경변수 화면에만 넣어주세요.
로컬에서 쓸 때는 `.env.local` 에 넣으면 되고, 이 파일은 이미 Git에서 제외돼 있습니다.

## 5. Vercel에 배포하기

**1단계 — 프로젝트 가져오기**

Vercel 대시보드 → **Add New** → **Project** → 이 GitHub 저장소를 **Import** 합니다.

프레임워크는 Next.js로 자동 인식되고, 빌드 명령·출력 경로도 기본값 그대로 두면 됩니다.
Node 버전도 `package.json` 에 적혀 있어 자동으로 22.x가 선택됩니다.

**2단계 — 환경변수 넣기**

Import 화면의 **Environment Variables** 에서 [4번 항목](#4-환경변수)의 값을 넣습니다.

**`Production`, `Preview`, `Development` 세 곳 모두에 넣어주세요.** Preview에 값이 없으면
브랜치 미리보기가 빈 화면처럼 동작합니다.

**3단계 — Deploy**

**Deploy** 를 누르고 기다립니다. 1~2분이면 끝납니다.

배포가 끝나면 `프로젝트이름.vercel.app` 주소가 나옵니다. 접속해서 키 입력 화면이 뜨고,
Notion에 넣어둔 키(예: `/example`)가 열리는지 확인해 보세요.

**4단계 — 도메인 연결 (선택)**

**Settings** → **Domains** 에서 원하는 주소를 연결합니다.
연결한 뒤에는 `NEXT_PUBLIC_SITE_URL` 을 그 주소로 바꾸고 **다시 배포**해 주세요.

**5단계 — Preview 배포 보호 (권장)**

Vercel의 브랜치 미리보기 주소(`*.vercel.app`)는 **누구나 접속할 수 있고 같은 환경변수를
씁니다.** 프로덕션 도메인에만 접근 제한을 걸어두면 이 주소로 우회됩니다.

**Settings** → **Deployment Protection** 에서 Preview에 보호를 켜두시길 권합니다.

## 6. 바로가기 운영하기

### 재배포는 필요 없습니다

Notion 표만 고치면 됩니다. 다만 **바로 반영되지는 않습니다** — 서비스가 Notion을 매번
읽지 않고 5분 주기로 모아서 읽기 때문입니다(Notion에는 초당 요청 한도가 있습니다).

| Notion에서 한 일 | 반영까지 |
|---|---|
| 기존 줄의 주소·제목·설명 수정 | 최대 5분 |
| `Enabled` → `Disabled` 로 변경, 줄 삭제 | 최대 5분 |
| **새 줄 추가** | 보통 5분, 드물게 최대 10분 |
| 속성 이름·타입 변경 | 이름을 되돌리거나 코드를 고쳐야 합니다 → [문제가 생겼을 때](#7-문제가-생겼을-때) |

새 키가 조금 더 걸리는 이유는, 아직 없던 키에 접속하면 그 "없음" 결과도 잠시 저장되기
때문입니다. 5분쯤 뒤 다시 시도해 보시면 됩니다.

**Redeploy를 눌러도 빨라지지 않습니다.** 페이지 캐시는 배포할 때 비워지지만, Notion에서
읽어둔 내용은 배포와 별개로 보관되기 때문입니다. 확실한 방법은 5분쯤 기다리는 것입니다.

수정하는 즉시 반영되게 하고 싶으시면 알려주세요 — Notion을 저장할 때 신호를 받아 바로
갱신하는 기능을 추가할 수 있습니다(지금은 쓰지 않는 기능을 열어두지 않으려고
일부러 넣지 않았습니다).

### 잠시 내리고 싶을 때

줄을 지우지 말고 `Enabled` 를 `Disabled` 로 바꿔주세요. 나중에 되돌리기 쉽고,
그동안 그 키는 "존재하지 않는 바로가기"로 안내됩니다.

### 키를 너무 짧게 만들지 마세요

`a`, `go` 처럼 1~2자 키는 아무나 찍어서 맞힐 수 있습니다. 내부 문서 주소를 담는다면
추측하기 어려운 이름을 쓰시는 편이 좋습니다.

이 서비스는 **검색엔진에 노출되지 않도록** 설정돼 있지만(모든 페이지 `noindex`,
`robots.txt` 차단, 바로가기 목록 공개 안 함), 키를 아는 사람은 누구나 볼 수 있습니다.

## 7. 문제가 생겼을 때

### 모든 키가 "존재하지 않는 바로가기"로 나옵니다

**대개 인테그레이션을 표에 연결하지 않은 경우입니다.**
[3번 항목의 2단계](#3-notion-인테그레이션-연결하기)를 다시 확인해 주세요.

Vercel의 **Deployments** → 해당 배포 → **Runtime Logs** 를 보시면 원인이 구분돼 찍힙니다:

| 로그에 보이는 말 | 뜻 | 할 일 |
|---|---|---|
| `object_not_found` | 표에 인테그레이션이 연결되지 않았습니다 | `⋯` → Connections 에서 추가 |
| `NOTION_TOKEN is invalid` | 토큰이 틀렸습니다 | 시크릿을 다시 복사해 넣기 |
| `Notion rejected the query` | 속성 이름·타입이 다릅니다 | 로그에 적힌 속성 확인 |
| `rate limited` | 요청이 너무 많습니다 | 잠시 후 자동 회복 |

### 특정 키만 안 열립니다

- `Enabled` 가 `Enabled` 로 선택돼 있는지 확인해 주세요 (비어 있으면 꺼진 상태입니다)
- `Key` 앞뒤에 공백이 들어갔는지 확인해 주세요 (보이지 않지만 자동으로 정리합니다)
- `URL` 이 `http://` 또는 `https://` 로 시작하는지 확인해 주세요. 그 외 형식은
  안전을 위해 무시합니다
- 방금 추가하셨다면 5분쯤 기다려 주세요

### 미리보기 이미지가 안 나옵니다

목적지 사이트가 미리보기 이미지(`og:image`)를 제공하지 않거나, 외부에서 가져가는 것을
막아둔 경우입니다. **정상 동작입니다** — 이미지 자리에 주소가 대신 표시됩니다.

실제로 이미지가 있는 사이트도 절반 정도만 성공하는 것이 보통입니다. 목적지 사이트의
HTTPS가 아직 준비되지 않은 경우에도 이미지가 나오지 않습니다.

### 같은 키가 두 줄에 있습니다

먼저 나온 줄이 쓰이고, 로그에 경고가 남습니다. 중복을 정리해 주세요.

## 8. 사이트 문구·이름 바꾸기

`site.config.ts` 한 파일만 고치면 됩니다.

```ts
export const CONFIG = {
  title: "CHEONGSANDO",                    // 헤더 로고, 브라우저 탭 제목
  description: "바로가기 키를 입력하면…",   // 검색 결과용 설명
  lang: "ko-KR",
  blogUrl: "https://cheongsan.com",        // 로고를 누르면 가는 곳
  notFoundMessage: "존재하지 않는 바로가기 키입니다.",
} as const
```

고친 뒤 GitHub에 올리면 Vercel이 자동으로 다시 배포합니다.

화면 색·글꼴은 [`app/globals.css`](app/globals.css) 위쪽의 색상 목록에 모여 있습니다.

## 9. 내 컴퓨터에서 실행해 보기

배포에는 필요하지 않지만, 미리 확인해 보고 싶을 때를 위한 안내입니다.

**Node 22** 가 필요합니다.

```bash
nvm use            # .nvmrc 에 22.14.0 이 적혀 있습니다
npm install
npm run dev        # http://localhost:3000
```

> `nvm` 명령을 찾을 수 없다면
> `export NVM_DIR="$HOME/.nvm" && . "$NVM_DIR/nvm.sh"` 를 먼저 실행해 주세요.
> Node 16 같은 낮은 버전에서는 `npm install` 이 바로 실패합니다.

**Notion 없이도 화면을 볼 수 있습니다.** `NOTION_TOKEN` 이 없으면 예시 데이터로 동작하므로,
입력 화면·확인 카드·이미지 없는 경우·다크 모드를 그대로 확인할 수 있습니다.

Notion에 연결해서 보시려면:

```bash
cp .env.example .env.local     # 파일을 열어 NOTION_TOKEN, NOTION_DATABASE_ID 채우기
npm run notion:datasource      # (선택) NOTION_DATA_SOURCE_ID 값 확인
npm run dev
```

그 외 명령:

```bash
npm test        # 자동 테스트
npm run build   # 배포와 같은 방식으로 빌드해 보기
npm run lint
```
